# Smart2Plant

**Your field, seen from space.** A crop-rotation planner and field monitor built on NASA Earth observation data.
NASA Space Apps Challenge 2026 · Challenge: *Field Shift: Adapting Farms with NASA Data* · Uruguay.

> Informative tool: it suggests, the farmer and their agronomist decide.

## Screens (agronomist workflow)
| Screen | What it does |
| --- | --- |
| Inicio / Home | What the app does, how to use it step by step, NASA data used, monitoring plans and prices |
| Mis campos / My fields | Portfolio of client fields with what needs attention first |
| 1 · Campo y parcelas | Draw the field and each plot on a 2D map (snapping to edges and corners) or split equally; per-plot plan (crop, sowing month, previous crop, tillage, irrigation); small animated 3D view |
| 2 · Predicción | Dry / normal / wet year per plot: yield, margin, water covered, soil loss vs. tolerance, main pest; timeline (greenness, soil water, erosion, demand vs. rain); water needs; pest calendar; most robust crop |
| 3 · Seguimiento satelital | Weekly, biweekly and monthly monitoring plans: usable images, cloud gaps, when each plan detects a problem; 2D NDVI map per capture; expected vs. seen per plot. Second tab: similar fields within a radius in km (slope, soil, crop), greenness this season and what neighbours did in the drought |
| 4 · Informes | Reports for the farmer, the landowner and a draft Soil Use Plan (PDF, WhatsApp, email hook), plus editable sheets to fill in (visit, PUMRS, pest scouting, sowing record): repeated fields typed once, optional autofill from the chosen plan, editable templates, Word .doc / PDF export |

The prediction engine is in `src/agro.ts` (water balance with NASA POWER ET0 and GPM IMERG rain, RUSLE with SRTM slope, FAO yield response, pest risk from weather). Prices, costs, soil K and bucket size are reference values to validate.

## Deploy (free)
- **Netlify:** `npm run build`, then drag the `dist/` folder to https://app.netlify.com/drop
- **Vercel:** import the GitHub repo, framework *Vite*, output `dist`.

Satellite map tiles (Esri World Imagery) load on the deployed site.

## Data: replace the demo data with the NASA pipeline
The app reads `public/data/fields/index.json` and `public/data/fields/<id>.json`.
**The current files are DEMO data** generated by `scripts/generate-data.mjs` (`npm run data`).
Have the Python pipeline write files with exactly this shape (see `src/types.ts`):

```
{ id, name, department, areaHa, polygon (GeoJSON),
  elevationGrid: { rows, cols, cellSizeM, values[] },            // SRTM
  monthly: [ { month, ndvi[], bareSoil[], rainMm, soilMoisture,  // HLS, GPM IMERG, SMAP
               tMaxC, tMinC, frostDays } ],                      // NASA POWER
  zones: [...], alerts: [...], rotations: [...], analogs: [...] }
```
Grid cells are row-major, row 0 = south edge. Then run `npm run build` again.

## Data sources
NASA HLS (Landsat + Sentinel-2), GPM IMERG, SMAP, NASA POWER, SRTM, ECOSTRESS, MODIS.
Local: CONEAT soils, INIA, INUMET, MGAP. Map imagery: Esri World Imagery.
